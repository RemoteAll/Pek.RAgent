# 安全审计报告（2026-10-27）

> 范围：Pek.RAgent 本轮在线终端/日志清理改动 + 星尘契约接口 + WAF/反代链路 + 出站 HTTP + DHDeploy 升级链路。
> 触发：用户指出「DHDeploy 无法正常升级」的根因未被提前发现，要求审计并评估隐患。
> 结论：**发现 1 个严重（反代免登录）、2 个高危（子用户终端 root shell、命令审计泄露口令）、3 个中危（WAF 空 UA 自锁、跨用户重置、真实 IP 失真）**；严重/高危/中危均已修复或有明确缓解，残余风险见第 5 节。

## 0. 用户原话

> 那要做一次安全审计，为什么我前面发现的问题你没有发现？这会造成多大的隐患

## 1. 为什么上次没发现（根因复盘）

上次定位 DHDeploy 升级失败时，我只做到两层就停了：

1. 查了 RAgent 的 `/GetServices` 路由，确认「有 `deny_remote`、无鉴权问题」；
2. 看到 DHDeploy 日志「星尘查不到服务 → 不猜路径 → 跳过」，把它归因于 DHDeploy 的路径推断缺陷（这确实是其中一层），v1.0.47 加了影子目录兜底后就结束了。

**漏掉的第三层**：`/GetServices` 是机器对机器调用，RAgent 的 WAF **默认会检查 UA**；当 WAF 开启 `block_empty_ua`（或 `loopback_bypass=false` 且 UA 为空）时，DHDeploy 的空 UA 请求会在到达路由前就被 403。「浏览器能打开 `/GetServices`、Agent 本机查询却失败」正是这个特征。我没有：

- 用**生产 WAF 配置**做一次端到端请求（空 UA / 非浏览器 UA / 反代头）；
- 盘点所有机器对机器调用及其 UA；
- 把「下载/自检成功但查不到星尘」继续追到 HTTP 状态码与 UA。

同类问题因此也漏了：反代下 `LocalOnly` 会把 `127.0.0.1` 当成本机，**远程用户直接免登录**；子用户终端虽然加了危险命令过滤，但**本质仍是 root shell**，白名单为空时等于不限制。这些都不是“再看一眼代码”能发现的，必须有**跨组件调用矩阵 + 攻击视角**。

## 2. 发现与定级

| # | 级别 | 问题 | 影响 | 状态 |
|---|---|---|---|---|
| 1 | **严重** | `WebAuthLevel=LocalOnly`（默认）+ 面板前有 nginx/TLS 反代时，`client_ip` 只看到 `127.0.0.1` → 所有远程请求被当成“本机”，**免登录获得管理员面板与 root 终端**；WAF 也因 `loopback_bypass` 整体放行 | 面板/终端/文件管理/服务控制全部暴露，等价服务器被接管 | **已修复** |
| 2 | **高危** | 子用户终端是服务账户权限（Linux 通常 root）；此前 `TerminalAllowedCommands` 留空=不限制，且危险命令是**字符串匹配**，可用引号拼接、`$()`、解释器（python/bash）、`find -exec` 等绕过 | 被授予 `terminal` 的普通用户可获得 root，等于提权 | **已修复（默认禁止 + 多层限制）** |
| 3 | **高危** | 命令审计把完整命令行落库，`mysql -pXXX`、`--token=...`、`Authorization: Bearer ...`、URL `?token=` 等会明文进入 `Agent_OperationLog`，有 `audit` 权限的人可读 | 凭据泄露，可横向登录数据库/接口 | **已修复（脱敏）** |
| 4 | **中危** | WAF `block_empty_ua` 开启后，RAgent/DHDeploy 的空 UA 机器调用被 403：升级静默跳过、健康检查误判、插件/证书拉取失败；DHDeploy 表现为“升级卡住” | 升级/运维链路失效，旧版本长期在线（错过安全补丁） | **已修复** |
| 5 | **中危** | `POST /star/termReset` 只校验登录，不校验会话归属；子用户知道 sid 可重置他人终端（拒绝服务/打断操作） | 跨用户干扰 | **已修复** |
| 6 | **中危** | 反代下审计 IP、登录限流、WAF Top IP 全部记为 `127.0.0.1`：审计失真、一人爆破可封禁所有用户、IP 黑名单失效 | 可观测性与限流失效 | **已修复（TrustForwardedFor）** |
| 7 | 低 | 管理员保留 ↑ 历史/行编辑，服务端行缓冲可能与 shell 实际行不一致，审计/二次确认可被历史命令绕过 | 管理员本身可信；若管理员账号被盗则审计不完整 | 已知边界，文档标注 |
| 8 | 低 | `/GetServices`、`/StopService` 等本机契约接口仅靠回环限制；同机任意本地用户/被攻陷应用可调用 | 本机横向移动/停服 | 保留（兼容 C# 契约），已拒绝带转发头的代理请求 |
| 9 | 信息 | 终端 WebSocket 支持 `?token=`，可能进入反代访问日志 | 令牌泄露风险 | 既有设计，建议用 Header/短时效 |

## 3. 已实施修复

### 3.1 反代免登录 / 真实 IP（严重 #1、#6）

- 新增配置 `TrustForwardedFor`（默认 **false**），面板可在线改，模板/README 同步。
- `WebPanel::effective_client_ip`：
  - 默认：对端回环但带 `X-Real-IP` / `X-Forwarded-For` → 按**代理来的远程请求**处理，`LocalOnly` 不再免登录；
  - 开启：仅对端回环才采纳转发头，优先 `X-Real-IP`，否则取 XFF **最后一段**（防客户端伪造左侧）。
- 登录限流、审计 IP、终端审计 IP 全部改用该口径。
- 星尘契约接口 `deny_remote` 同样拒绝“回环 + 转发头但未信任”的请求。
- WAF 开启 `set_trust_forwarded_for(true)`（仅回环对端采纳），避免反代后整体放行与 IP 统计失真。
- 新增单测 `forwarded_for_is_never_trusted_by_default` 覆盖 6 种组合。

> 部署要求：反代必须设置 `X-Real-IP $remote_addr`，或**覆盖**（`proxy_set_header X-Forwarded-For $remote_addr`）而不是追加；直连部署保持 `TrustForwardedFor=false`。

### 3.2 子用户终端（高危 #2）

- `term_ws`：非管理员且 `TerminalAllowedCommands` 为空 → **403 拒绝**（不再默认给 root shell）。
- `decide_line` 对子用户增加三层：
  1. 必须命中白名单前缀；
  2. 拒绝 shell 元字符（`; & | $ \` ( ) < > \\ " ' * ? [ ] { }`、换行）——防拼接/替换/重定向；
  3. 拒绝解释器与逃逸类程序（bash/sh/python/perl/node/awk/sed/find/xargs/env/sudo/docker/kubectl/curl/wget/ssh/chmod/chown/systemctl-run 等），即使误写进白名单也拒绝。
- 会话归属：`termReset` 校验所有者，子用户只能重置自己的会话。
- 新增单测 `sub_user_requires_whitelist_and_rejects_shell_escapes`、`policy_branches`。

**定级说明**：这仍是“运维护栏”，不是安全沙箱。白名单里若放入 `systemctl` 等特权命令，仍可影响系统；真正隔离需独立 OS 用户/容器。

### 3.3 命令审计脱敏（高危 #3）

- 新增 `redact_command`：`mysql -pXXX`、`--password/--token/--secret/--api-key`、`Authorization: Bearer ...`、URL `?token=`/`password=`、`redis-cli -a` 统一替换为 `***`。
- 终端审计与“二次确认后执行”审计都使用脱敏后的命令；终端输出本身不变。
- 新增单测 `audit_redacts_common_secrets`。

### 3.4 WAF 空 UA 自锁（中危 #4）

- `util::user_agent()` = `pek-ragent/<版本>`。
- 已覆盖 RAgent 全部出站调用：健康检查、证书材料拉取、插件/升级下载、DHDeploy 面板探活/下发、CLI 本机 API。
- DHDeploy 侧（v1.0.53 未提交改动）已给 `/GetServices` 带 `dhdeploy-agent/<版本>`，并只查 Rust 星尘 5501。
- 文档/模板提示：`block_empty_ua=true` 前必须确认所有内部调用带 UA。

### 3.5 其他

- 面板配置页新增 `TrustForwardedFor` 说明；README 终端配置表把白名单语义改为「留空 = 禁止子用户」。
- `cargo test --bin pek-ragent`：**212 passed / 0 failed / 2 ignored**；`cargo clippy --all-targets`：**0 warning**。

## 4. 隐患评估（回答“会造成多大隐患”）

- **本次直接损失**：DHDeploy 升级静默跳过属于**可用性/补丁时效**问题，不是数据泄露；但会让节点长期停留在旧版本，若旧版本有已知漏洞，等于持续暴露。
- **更严重的是同类思维盲区**：反代免登录是**直接接管服务器**级别；子用户终端是**提权**级别；审计明文口令是**凭据泄露**级别。三者都不是本次改动新增，但都属于“只看单点代码、不做攻击视角与端到端验证”会漏掉的问题。
- **可被利用条件**：
  - #1 需要面板经 nginx/反代暴露（很多生产会这样）；
  - #2 需要给子用户勾选 `terminal` 权限；
  - #3 需要用户在终端里把口令写在命令行（很常见）。
- **修复后**：默认配置下上述三条主路径已关闭；剩余风险集中在“管理员主动开启的配置”和“白名单本身给了特权命令”。

## 5. 残余风险与后续建议

1. **真正的子用户隔离**：建议后续给子用户终端改用独立低权限 OS 用户 + 受限执行器（或容器），不再共用 root shell；当前白名单只能降低风险。
2. **本机契约接口加共享令牌**：`/GetServices` 等可增加 `X-Agent-Token`（DHDeploy 与 RAgent 预置同一密钥），防止同机低权限进程调用；需与 C# 版兼容评估。
3. **WAF 首段 XFF 口径**：Pek.RWaf 仍取 XFF 第一段；若反代采用追加模式，客户端可伪造左侧。建议统一改为 `X-Real-IP` 或最后一段，并加回归测试。
4. **终端令牌传输**：WebSocket `?token=` 建议改为短期一次性票据，避免反代日志泄露。
5. **管理员审计完整性**：如需对管理员也强制审计，应接入 shell 侧钩子（bash `PROMPT_COMMAND` / PowerShell history）而不是行缓冲。
6. **内部调用清单化**：把“谁调用谁、用什么 UA/认证”写入项目接续文档，新增机器接口必须过 WAF 三态测试（空 UA / 机器 UA / 浏览器 UA）。

## 6. 防复发（流程）

- 新增/修改任何机器对机器 HTTP 调用：必须声明 UA + 认证方式，并补一条“WAF 开启 `block_empty_ua` 仍可用”的测试。
- 任何“本机免登录/回环信任”逻辑：必须测试“回环 + 转发头”场景，默认按远程处理。
- 任何给子用户开放的命令执行能力：默认拒绝，白名单 + 元字符/解释器双重限制，并在文档标注“非沙箱”。
- 审计落库前统一走脱敏函数，新增敏感参数要补测试。
